# 6.2 Unit economics - cost per task, inference cost, gross margin
> In AI products, the unit that matters is the cost of one completed task, and gross margin is set by how many tasks a paying user triggers.

## Concept
Traditional SaaS has near-zero marginal cost per user. AI features add inference cost on every call, so the unit economics must be built bottom-up:

**Cost per task** = calls per task x [(input tokens x input price) + (output tokens x output price)] + retrieval/tool costs + infra overhead (+ retries and fallbacks)

Calls per task matters: an agent or a reasoning model may make many calls or produce thousands of hidden reasoning tokens for one user request, so a feature that looks cheap per call can be expensive per task. Measure **cost per successful task** (total cost ÷ tasks that actually succeeded), because failed attempts still cost money.

Worked example (illustrative prices): a support answer uses 3,000 input tokens and 400 output tokens. At $1 per million input and $4 per million output, that is $0.003 + $0.0016 ≈ $0.005 per call. With 1.3 calls per task (retries, a safety check) and an 80% success rate, cost per successful task ≈ $0.005 x 1.3 ÷ 0.8 ≈ $0.008.

**Cost per paying user** = tasks per user per month x cost per task

**Gross margin** = (revenue per user - cost of serving that user) / revenue per user, where cost of serving (COGS) includes inference, hosting, and third-party APIs.

Classic SaaS gross margins are often 75-80%+; AI-heavy products have commonly reported lower margins because inference is a real COGS line.

Key levers:
- **Model choice:** a smaller model can be 10x cheaper per token or more, and is often good enough for a narrow task.
- **Prompt length and context:** long retrieved context inflates input tokens; trim it.
- **Output length:** output tokens are usually priced higher; cap or structure responses.
- **Caching:** repeated prompts or semantic caches cut cost.
- **Routing:** send easy requests to cheap models, hard ones to expensive models.
- **Retries:** failed or re-generated calls are hidden cost; measure them.
- **Usage distribution:** averages hide heavy users. A small group of power users can make a plan unprofitable, so model the tail.

A PM should be able to write the sensitivity table: how margin changes if tokens per task go up 2x, if price per token falls 50%, or if the feature's adoption doubles. The question to answer is whether the feature stays profitable at the 95th-percentile user, not the average one.

## Real-world examples
- **GitHub Copilot** - The Wall Street Journal reported in October 2023 that GitHub was losing money on many users of its $10-a-month plan, with heavy users costing far more than they paid (the report cited unnamed sources). In 2025 GitHub added monthly allowances of "premium requests" for advanced models, with paid overage: a usage-metered layer on top of a per-seat plan.
- **Intercom Fin** - priced per resolution (launched at $0.99 per resolution in 2023), so Intercom's cost per resolution, including failed attempts that do not resolve, has to stay well below that price.
- **Indic-language products** - with older tokenisers, the same sentence in Hindi or Tamil could take several times more tokens than in English, so cost per task differed by language. Tokeniser improvements (for example, OpenAI's GPT-4o tokeniser in 2024) narrowed the gap; measure tokens per task for each language before setting prices.

## Practice questions
1. Your AI summarizer costs Rs 4 per summary and users generate 30 per month on a Rs 499 plan. Is the feature profitable? What would you change?
   - Outline: 30 x Rs 4 = Rs 120, about 24% of plan price before other costs; check the tail users, route short documents to a cheaper model, cap length.
2. How would you forecast AI COGS for a launch with no usage data?
   - Outline: estimate tokens per task from prototype logs, a range of tasks per user, then a best/base/worst case; plan to revisit after two weeks.
3. Why might a feature with 70% gross margin on average still be a problem?
   - Outline: the average hides heavy users who may be margin-negative; usage grows over time; agent features or longer contexts can raise tokens per task; price competition may cut revenue; and 70% is below typical SaaS margins, which affects valuation.
4. What metric would you put on a dashboard to catch cost regressions early?
   - Outline: cost per successful task by feature and model version, tokens per task (input and output), calls per task, and the share of users whose cost exceeds their revenue, with alerts on week-over-week jumps.
