# 6.4 Defensibility - proprietary data, distribution, workflow integration, switching costs
> If every competitor can call the same model, the moat has to come from data, distribution, the workflow you sit in, or the cost of leaving.

## Concept
Model quality is commoditizing: capability that was frontier a year ago becomes cheap and widely available. A wrapper around a model has little defensibility, so the PM must answer "why won't a well-funded competitor, or the model vendor itself, copy this in a quarter?"

Sources of defensibility for AI products:
- **Proprietary data:** unique, consented, labelled data or domain corpora that improve the product and are hard to obtain. Data alone is not a moat unless it is used to improve outcomes (see 4.2 on data flywheels).
- **Distribution:** an existing user base, channel or platform that the AI feature plugs into (for example, a messaging app or an e-commerce checkout).
- **Workflow integration:** the AI sits inside a system of record, with permissions, approvals and integrations. Removing it breaks daily work.
- **Switching costs:** data gravity, retrained teams, custom configurations, integrations and contracts.
- **Trust and brand:** in regulated or high-stakes domains, a proven safety record is slow to replicate.
- **Cost position:** a lower cost per task that lets you price below rivals and still earn margin.

Test: remove the model vendor from the equation. What is left that a customer would miss? If the answer is only the prompt, the moat is weak.

## Real-world examples
- **Bloomberg** - its moat is proprietary financial data plus the Terminal workflow. It trained BloombergGPT (2023), but general frontier models soon matched it on many finance tasks, which suggests the durable moat is the data and workflow, not the model.
- **Microsoft 365 Copilot** - draws on the Microsoft Graph of user documents and emails and sits inside existing Office workflows, an example of distribution plus workflow integration.
- **Blinkit (Feb 2023 teardown)** - the teardown's ideas (ingredient kits, subscriptions for daily essentials) lean on an existing dense delivery network and user habit, which is distribution-based defensibility.
- **Epic Systems (US healthcare)** - deep EHR integration creates switching costs that a new AI tool must work inside rather than replace; Epic has added generative AI features (such as drafting replies to patient messages, built with Microsoft) inside its own workflow.
- **Cursor vs GitHub Copilot** - the AI code editor Cursor grew quickly despite Copilot's distribution advantage inside VS Code and GitHub, a reminder that distribution slows rivals but does not stop a clearly better workflow.

## Practice questions
1. A startup offers an AI legal-drafting tool built on a frontier API. Where is its moat, and how would you test it?
   - Outline: check whether it owns firm-specific templates and clause data, integrations with document systems, and retention after a model upgrade; run a churn-risk test with a vendor-neutral baseline.
2. Why might a model vendor be a competitor to your product?
   - Outline: vendors see aggregate demand through their APIs and move up the stack into popular use cases (for example, assistants adding coding, search, and document features). If your product is a thin wrapper on their model, a single launch can match it.
3. Which defensibility lever matters most for an Indian consumer app with a large user base?
   - Outline: distribution and habit first (the user base and daily use), then proprietary behavioural data in local languages that improves the feature, and trust (payments, KYC) in regulated categories.
4. How would you measure switching costs in a product?
   - Outline: integrations per account, data volume stored, number of customised workflows, time to migrate, and churn after competitor launches or price increases.
